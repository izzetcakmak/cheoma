Lay a tile. Make a wish. Raise the roof — together.  Digital giwa-bulsa (기와불사): a communal 64×32 roof of 2,048 wish-inscribed tiles, each a fully on-chain ERC-721 on GIWA Sepolia. One tile is fragile; together they make a roof.

The Product

  • Claim a tile. Pick any empty cell on a shared 64×32 roof — 2,048 tiles, one canvas for the whole community.
  • Glaze & inscribe. Choose a glaze color (uint24 RGB) and ink a wish (≤ 140 bytes), exactly as donors ink wishes on temple roof tiles before a hall is raised.
  • Fully on-chain NFT. Each tile mints as an ERC-721 whose sumaksae (수막새) petal art and JSON metadata are generated inside the contract — no IPFS, no server.
  • Optional donation. Any ETH sent with layTile is forwarded atomically to a public roofFund — the on-chain analogue of a temple tile donation.
  • The roof rises together. Live shared canvas; a RoofMilestone event fires every 256 tiles; max 16 tiles per wallet keeps the roof plural.

Architecture — no backend, no IPFS, no indexer

The UI paints all 2,048 tiles with a few batched getRange(start,count) calls and keeps them live from TileLaid events — the chain itself is the database and the CDN.

Contract Internals

  • Zero-dependency ERC-721. Minimal implementation written from scratch in a single file — no OpenZeppelin import in production bytecode, every line auditable in one sitting.
  • One storage slot per tile. The hot fields of Tile pack into 31 bytes — a single SSTORE covers giver, glaze and timestamp:
fieldtypebytesslot
giveraddress20slot 0 (31 / 32 B)
coloruint243
laidAtuint648
wishstring≤140slot 1+
  • On-chain art. tileSVG(id) draws a sumaksae end-cap — 6–8 petals deterministically seeded by tile id, filled with the giver's glaze — and tokenURI wraps it as base64 JSON data URI. Marketplaces render it with zero external fetches.
  • Invariants. One giver per tile, forever — the original giver record survives NFT transfers. Wish ≤ 140 bytes, id < 2048, ≤ 16 tiles per wallet, donations pass through in the same tx.
  • Cost. ~160k gas per layTile — cents on an L2, dominated by the wish string.

Why GIWA — technically

A communal canvas dies when feedback is slow. Time from click to seeing your tile on the roof:

  • Cultural DNA. GIWA is named after the roof tile; CHEOMA turns the chain's own metaphor into its first communal ritual.
  • Consumer-simple. One tx, three inputs — a natural GIWA Wallet mini-app surface (Q3 2026, with Dojang attestations for verified givers).

Security Posture

  • No admin keys. No owner-only functions that touch tiles, art or funds. Nobody can edit, censor or reassign a laid tile — including the deployer.
  • No upgradability. Plain immutable contract — no proxy, no delegatecall surface, what you verified is what runs forever.
  • No custody. The contract holds zero ETH: donations forward atomically to the public roofFund inside layTile; the tx reverts if the transfer fails.
  • Bounded state. Hard caps everywhere — 2,048 tiles, 140-byte wishes, 16 tiles per wallet — no unbounded loops, no griefing surface.
  • Tested. Full Foundry suite, 14 tests: mint rules, double-lay rejection, wish-length limits, per-wallet cap, donation forwarding, transfer-vs-giver invariant, tokenURI/SVG output.
